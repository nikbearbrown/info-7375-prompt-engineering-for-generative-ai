Agentic patterns · Overview

Three classes of agentic pattern

The model decides, code decides, or a check decides.

This deck is the overview for the whole set. It defines an agentic pattern and the agentic loop, then the three classes every pattern belongs to: reasoning, workflow and loop check. Each class gets a definition and a real example from the bearbrown.co agent library. The twenty detailed patterns have their own decks; this one is about the three classes.

The claim

In everyday speech, all three are workflows. What separates them is what decides the next step.

Any agent system is a workflow in the loose sense: a series of steps that turns a request into a result. The three classes are three answers to one question. Who or what picks the next step? In a reasoning pattern, the model does. In a workflow pattern, the code does. In a loop check, a check does: the step repeats until the check passes.

Definitions

Two terms first

An agentic pattern, and the agentic loop

  • Agentic pattern. A reusable structure for an agent's work: which steps run, in what order, and what decides the next one. It is not a prompt template.
  • Agentic loop. A model proposes an action, the program around it runs the action, the result comes back, and the model proposes again, until something stops the loop.
  • A stopped loop is not a right answer. "Finished" means the loop ended. Whether the result is right is a separate check.

Sources: Design of Agentic Systems with Case Studies, Chapter 3 ("a rule for which operations run in what order, and what triggers the next one"); INFO 7375, Chapter 4, the agent loop.

Two words do most of the work in this deck. A pattern is a structure, not a set of words in a prompt: it fixes which steps can happen and what chooses among them. The agentic loop is the engine underneath: propose, run, observe, repeat. The three classes differ in where the choice of the next step sits inside or around that loop.

Class one

Reasoning

The model decides the next step

Reasoning first, because it is what most people picture when they hear the word agent: a model that looks at a problem and decides what to do.

Definition

Reasoning, defined

A reasoning pattern is how a model orders its own steps

  • What decides. The model. Each time round the loop, it reads what it has and picks the next step or tool.
  • What you gain. It can change course when a result surprises it.
  • What it costs. It is harder to predict and to test, and every result it reads takes up context.
  • The detailed patterns. ReAct, Plan-and-Execute, ReWOO, Reflection, Tree-of-Thoughts.

Source: Design of Agentic Systems with Case Studies, Chapter 3.

The program still runs the loop and the tools. What changes is who chooses. In a reasoning pattern the choice of the next action is the model's, made fresh after every result. That is the source of both its strength and its risk.

Real workflow · not run

A real example: a résumé-screening agent

The model reads the résumé and picks the tools

Source: bearbrown.co/agents, "AI Agent - Cv Resume - Automated Screening, Sorting, Rating and Tracker System", an n8n workflow read from its file, not run. The decision shown is an example.

On entering: a new résumé lands in a folder.

Step 1: the program pulls the résumé's text and the job description and hands both to the model. So far this is fixed code.

Step 2: the model compares them and decides: reject, keep in view, or shortlist. Here, say, shortlist.

Step 3: the model then picks its tools. It moves the file to the shortlisted folder, updates the tracker and emails the candidate. The other two folder tools go unused.

Step 4: no line of code chooses the folder. The model does. And it emails the candidate with no person in between, which is a design choice worth questioning.

Class two

Workflow

Code decides the next step

Everything in this deck is a workflow in the everyday sense. In this class the word has a narrower meaning: the order of the steps is fixed in code.

Definition

Workflow, defined

A workflow pattern fixes the steps and their order in code

  • What decides. The code. A model can do some of the steps, but it never chooses which step comes next.
  • What you gain. It is predictable, cheap to run and easy to test, step by step.
  • What it costs. It only handles the cases its builder planned for.
  • Five ways to wire it. Prompt chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer.

Source: Anthropic, "Building Effective Agents": workflows are "systems where LLMs and tools are orchestrated through predefined code paths".

Using a model does not make something an agent. A workflow can call a model at every step and still be a workflow, because the code, not the model, decides what happens next. The five standard ways of wiring model calls are the subject of the film "Five Ways to Wire an Agent".

Real workflow · not run

A real example: the same job, built as a workflow

A model does four steps and chooses none of them

Source: bearbrown.co/agents, "Automated Resume Review System Using OpenAI + Google Sheets", an n8n workflow read from its file, not run.

On entering: the same job as the agent: screen a résumé.

Step 1: the path. A form brings in the résumé, the text is pulled out, two extractions run side by side, they are merged, summarized, rated and written to a spreadsheet.

Step 2: four of those steps are done by a model: the two extractions, the summary and the rating.

Step 3: the arrows are the code. They fix the order, and the model never picks the next step.

Step 4: the run ends at a sheet that a person reads. Compare the agent, which emailed the candidate itself.

Class three

Loop check

A check decides whether to go round again

The third class is about stopping. A loop check repeats a step until something outside the step says it is good enough.

Definition

Loop check, defined

A loop check repeats a step until a real check passes

  • Three parts. The step, the check, and a stop rule (how many tries at most).
  • What decides. The check, not the agent saying it is done.
  • What it costs. It is only as good as its check. A check that cannot fail proves nothing, and a loop with no stop rule may never end.
  • The detailed patterns. Burn down a worklist, maker is not the checker, evidence ledger, replay until clean, and six more.

Source: the Forward Future Loop Library, grouped into ten loop patterns.

A loop is a prompt plus a real check plus a stop rule. The check can be code, a test, a second model, or a person. What makes it a loop check is that the result of the check, not the agent's own report, decides whether to go round again.

Real workflow · not run

A real example: the check is code

Write a tweet, check its length, write again if it fails

Source: bearbrown.co/agents, "Configure influencer profile", an n8n workflow read from its file, not run.

On entering: a workflow that posts a tweet every six hours.

Step 1: a profile sets the topic and style, and a model writes a tweet.

Step 2: a check, in plain code: is the tweet longer than 280 characters?

Step 3: if it is, the loop goes round and the model writes again. If not, the tweet is posted.

Step 4: two weaknesses. There is no limit on the number of tries, so nothing stops an endless loop. And the check measures length, not whether the tweet is true or wise.

Real workflow · not run

A real example: the check is a person

Draft a reply, ask a person, write again if they say no

Source: bearbrown.co/agents, "AI Email processing autoresponder with approval (Yes/No)", an n8n workflow read from its file, not run.

On entering: an email arrives at a business address.

Step 1: a model drafts a reply, looking up company documents as it goes, and the draft is sent to a person.

Step 2: the person approves or not. Approved replies are sent.

Step 3: if not, the model writes again. The check here is a person. And the model inside is an agent, so this is a reasoning pattern running inside a loop check.

Conceptual illustration

How to tell them apart

Three questions, asked of any agent

Sources: Design of Agentic Systems, Chapter 3. Anthropic, "Building Effective Agents".

On entering: three questions to ask of any system.

Step 1: does the model choose the next step or tool? Then that part is reasoning.

Step 2: is the order of the steps fixed in code? Then that part is a workflow.

Step 3: does it repeat until a check passes? Then that part is a loop check. Real systems mix them: the email system is an agent inside a loop check, and the résumé workflow could hold a loop. Ask the questions of each part.

Takeaway

Ask who decides the next step: the model, the code, or a check.

Those three answers are the three classes. Reasoning gives you adaptation and costs you predictability. A workflow gives you predictability and costs you flexibility. A loop check keeps a run honest, but only if its check can fail and its stop rule exists. The twenty detailed patterns, each in its own deck, are variations inside these three.
