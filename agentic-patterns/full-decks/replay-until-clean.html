Replay until clean

Start from nothing. Fix what stops you. Start again.

This deck covers one loop pattern: replay until clean. It shows the shape of the pattern, the nine loops that use it, the way it fails, and how to pick it.

Conceptual illustration

Where this pattern sits

Twenty patterns in three families

Sources: Design of Agentic Systems with Case Studies, Chapter 3. Anthropic, "Building Effective Agents". The Forward Future Loop Library (85 loops).

On entering: an empty map. The set of decks covers twenty patterns, grouped by the question each family answers.

Step 1: reasoning patterns. These describe how one agent orders its own thinking and tool calls.

Step 2: workflow patterns. These describe how several model calls are wired together.

Step 3: loop patterns. These are grouped by the check that keeps a long run honest.

Step 4: this deck is Replay until clean, the sixth loop pattern.

The claim

One pass can be luck, or it can be leftover state. Run the whole thing again from nothing until it comes through clean.

A loop is a prompt plus a real check plus a stop rule. In this pattern the check is a clean replay: the same scenario, started from nothing.

Say this plainly: the ten loop patterns are a grouping made by reading a catalog of 85 submitted loops. The grouping is a judgment, and none of these loops has been tested on real runs for this deck. Treat what follows as a synthesis from reading, not as results.

Part one

The shape

The same scenario, from scratch, until a clean run

Two slides: the cycle with its check and its stop rule, and one replay drawn run by run.

Conceptual illustration

Structure

Every fix sends the run back to the very start

Source: the loop tree, pattern 6. Loops from the Forward Future Loop Library.

On entering: three empty places.

Step 1: the problem. It works for the people who built it, or it passes once by luck.

Step 2: run the same scenario from scratch.

Step 3: the run finds an obstacle. Fix that obstacle.

Step 4: restart the whole thing. Do not resume from where it stopped.

Step 5: stop after a clean run, or after N clean runs in a row. In the terms of a loop, the real check is the clean replay and the stop rule is the clean run or the streak.

Simulation (seeded)

One replay, run by run

Each run gets further, and every run starts at step 1

Source: the loop tree, pattern 6, and loop 039. The runs are a seeded simulation; counts are computed in code.

On entering: a first-time setup of eight steps. Three of the steps hide an obstacle. Their positions come from a seeded draw, so every replay of this slide matches.

Step 1: run 1 starts at step 1 and stops at the first obstacle. That obstacle is fixed.

Step 2: run 2 starts again at step 1. It passes the fixed step and stops at the next obstacle.

Step 3: run 3, from step 1 again, reaches the third obstacle.

Step 4: run 4 goes from step 1 to step 8 with nothing in the way. That is the clean run.

Step 5: the cost. Four runs and 21 steps for one clean run of 8. The entry for the easy onboarding loop says it directly: restarting the whole flow is slow.

Simulation (seeded)

The streak as a stop rule

One failure sends the streak back to zero

Source: loops 009 and 044, Forward Future Loop Library. The runs are a seeded simulation; every count is computed in code.

On entering: the bar is five passes in a row, chosen before the first run. The suite starts with three flaky causes.

Step 1: one pass, then a failure. The streak restarts at zero. In the quality streak loop the failure becomes permanent regression coverage. In the test stabilizer loop one root cause is fixed.

Step 2: two passes, then a second failure. Back to zero again.

Step 3: four passes in a row, one short of the bar, and then a failure. The streak is zero again. This is why the entries call the streak a tough bar that is hard to fake.

Step 4: five in a row. Stop. It took 15 full runs, and the entries name that cost: many full runs cost time. This blends two loops, 009 and 044, into one picture.

Part three

How it fails

Leftover state makes a broken run look clean

The pattern needs one thing: a truly clean start. Without it the replay is not a replay.

Illustrative data

The failure

A run can pass because of what the last run left behind

Source: the loop tree, pattern 6, "Needs" and "Fails when". The two runs are illustrative.

On entering: the same eight steps, about to be run twice.

Step 1: restarted on the same machine, the run passes every step. It looks clean.

Step 2: look at what earlier runs left behind: cookies, accounts, caches. Step 5 passed only because of them.

Step 3: restarted from a truly clean start, the same run stops at step 5. The obstacle was there all along.

Step 4: the pattern needs a truly clean start. It fails when leftover state makes the run look fine. The two runs on this slide are made up to show the point.

Part four

When to use it

It works for the builders. Does it work from nothing?

How to pick the pattern and the child loop, the pattern it is most easily confused with, and a checklist.

Conceptual illustration

The decision

Pick the pattern from the problem, then the closest child

Source: the loop tree, "How to use the tree" and patterns 2 and 6. Loops from the Forward Future Loop Library.

On entering: the tree is used top down.

Step 1: start from the problem you have. If it works for the people who built it, or passed once by luck, the pattern is replay until clean.

Step 2: then pick the child closest to your subject: a setup or restore from nothing, one task scored the same way each pass, or a suite that must pass N times in a row.

Step 3: if none fits, write your own child. Keep the pattern's shape and supply your own check.

Step 4: the pair to tell apart. Both fix things one after another. The difference is the check. Burn down a worklist reruns the same scan and stops when the list is empty. Replay until clean restarts the whole scenario and stops after a clean run. The loop tree does not compare the two directly; this contrast is built from their shape lines.

Conceptual illustration

Checklist

Seven checks before you run a replay loop

Source: the loop tree, pattern 6, and the entries for loops 009, 036 and 044. Loops from the Forward Future Loop Library.

Steps 1 to 3: when the pattern fits. The first is its problem, the second its shape, the third what it needs.

Steps 4 to 7: when it breaks. Leftover state is the loop tree's own failure. The other three come from the cautions in the loop entries, which are a reading of the catalog and not the catalog's own words: skipped hard cases, a quarantined test, and a score that is a judgment.

Takeaway

A pass counts when the run started from nothing. Restart the whole thing, and choose the streak before you begin.

What would change this advice: a replay you cannot start clean is not this pattern, and a check that is a judgment needs a second reader. Next in the set: Plan before building, for an idea that is still too vague to hand to an agent.
