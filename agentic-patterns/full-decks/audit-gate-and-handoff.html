Agentic patterns · Loop

Audit, gate and handoff

Inspect, give a verdict, hand control back.

This deck covers one loop pattern: the loops whose job is to stop. It shows the shape, the ten loops that share it, the way it fails, and when to use it.

Conceptual illustration

Where this pattern sits

Twenty patterns in three families

Sources: Design of Agentic Systems with Case Studies, Chapter 3. Anthropic, "Building Effective Agents". The Forward Future Loop Library (85 loops).

On entering: an empty map. The set of decks covers twenty patterns, grouped by the question each family answers.

Step 1: reasoning patterns. These describe how one agent orders its own thinking and tool calls.

Step 2: workflow patterns. These describe how several model calls are wired together.

Step 3: loop patterns. These are grouped by the check that keeps a long run honest.

Step 4: this deck is the ninth loop pattern: audit, gate and handoff.

The claim

Some loops exist to stop. They inspect, give a verdict with evidence, and return control to a person. The verdict is not permission.

A loop is a prompt plus a real check plus a stop rule. In this pattern the stop rule carries the weight: the loop ends and a person decides.

Say this plainly: the loops come from a public library of submitted ideas. Grouping them into ten patterns is a judgment made from reading them. None of it has been tested on real agent runs. The same reading calls this pattern one of the weakest on its own, because it stops work and does not improve it.

The ten loops

Ten loops stop, report or hand over in three ways

Source: the loop tree, pattern 9. Loops from the Forward Future Loop Library.

Step 1: read-only audits. 048 audits a project from current evidence. 058 audits your active loops and gives each exactly one status. 081 checks whether an agent workspace can be restarted. 057 finds recurring work that no loop owns and recommends one bounded manual trial.

Step 2: exit gates and handoff notes. 051 evaluates the next sensible action after a task and hands control back. 066 writes a handoff before a session ends. 084 writes a before-state and a prediction before each meaningful action.

Step 3: spend and release gates. 074 checks signed attestations before an agent spends on a paid API. 013 keeps stale or unfinished work out of a batch release. 017 moves one customer priority into a gradually released system, with approvals.

Step 4: the count, added in code, and the problem they share.

Conceptual illustration

One loop, walked through

066: the note records five things, and starts nothing

Source: loop 066, The restartable handoff loop, Forward Future Loop Library. The one-line glosses are this deck's.

On entering: an empty note. The loop runs before a session ends, so the next person or agent can resume without guessing.

Steps 1 to 5: the five things it records: state, evidence, risks, untouched scope, and one safe next action. The short phrase beside each name is my gloss, not the library's wording.

Step 6: the two limits from the entry. Only verified state may be recorded. The handoff is not permission to start the next action.

Illustrative data

One loop, walked through

084: write the prediction first, then check it

Source: loop 084, The world-state accountability loop, Forward Future Loop Library. The two actions and their numbers are made up.

On entering: two actions in a made-up task: replacing an old configuration key.

Step 1: before the first action the agent writes the before-state and a prediction.

Step 2: after the action it checks the evidence. Both predicted values held, so the decision is continue. The comparison is done in code.

Step 3: the same two notes before the second action.

Step 4: this time neither value matches the prediction. The decision is stop. The entry's stated benefit is that this catches wrong assumptions early. Its stated costs are overhead on every action, and that boundaries on production, money and security still need human approval.

Part three

How it fails

A GO is read as permission

The pattern needs one thing: the discipline to not act on the verdict.

Illustrative data

Needs and failure

A GO names the next action. It does not authorize it.

Source: the loop tree, pattern 9, "Needs" and "Fails when", and the entry for loop 051. The two runs are illustrative.

Step 1: the pattern as intended. The agent inspects and returns a verdict: GO, with evidence.

Step 2: control goes back. A person decides, and the next action runs with approval. Actions with no person approving: zero.

Step 3: the same inspection and the same verdict.

Step 4: this time the agent reads its own GO and keeps acting. In this made-up run it takes three more actions, counted in code, and no person approved any of them.

Step 5: the pattern's stated need and failure. The loop 051 entry says the same thing about its own GO.

Part four

When to use it

When the agent should stop and a person should decide

Pick the pattern from the problem you have, then the loop closest to your subject.

Conceptual illustration

The decision

Pick the pattern from the problem you have

Source: the loop tree, patterns 8 and 9 and "How to use the tree". Loops from the Forward Future Loop Library.

Step 1: if the problem is that the agent should stop, report or hand over, this is the pattern.

Step 2: if the problem is recurring work that should happen without anyone remembering, that is standing watch, the pattern before this one.

Step 3: the pair to tell apart. This pattern inspects, gives a verdict and returns control to a human. Standing watch wakes on a schedule and does one bounded thing or nothing. Both lines are the loop tree's shapes.

Step 4: the honest part. The loop tree calls this one of the weakest patterns on its own, because it stops work and does not improve it. That is a judgment from reading the loops, not from running them.

Conceptual illustration

Checklist

Six checks before you run an audit, gate or handoff loop

Source: the loop tree, pattern 9, and the entries for loops 048 and 066. Loops from the Forward Future Loop Library.

Steps 1 to 3: when it fits. The problem is stopping, a person is there to take the verdict, and the loop only inspects or sits in front of a spend or a release.

Steps 4 to 6: when it breaks. A GO is read as permission. A handoff records state nobody verified. Or you expect the loop to improve the work, when all it does is stop it.

Takeaway

An audit, a gate or a handoff ends with a person deciding. A GO names the next action. It does not authorize it.

What would change this: results from real runs, which nobody in this chain has. Next in the set: controlled experiment, the last loop pattern and the odd one out.
