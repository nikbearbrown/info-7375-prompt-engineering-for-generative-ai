Burn down a worklist

Scan, fix the top item, run the same scan again.

This deck covers one loop pattern: burn down a worklist. It shows the shape of the loop, the sixteen published loops that follow it, the way it fails, and how to decide whether it fits.

Conceptual illustration

Where this pattern sits

Twenty patterns in three families

Sources: Design of Agentic Systems with Case Studies, Chapter 3. Anthropic, "Building Effective Agents". The Forward Future Loop Library (85 loops).

On entering: an empty map. The set of decks covers twenty patterns, grouped by the question each family answers.

Step 1: reasoning patterns. These describe how one agent orders its own thinking and tool calls.

Step 2: workflow patterns. These describe how several model calls are wired together.

Step 3: loop patterns. These are grouped by the check that keeps a long run honest.

Step 4: this deck is Burn down a worklist, the second loop pattern.

The claim

A worklist loop is only as honest as its scan. The list can get shorter without the work getting done.

A loop is a prompt plus a real check plus a stop rule. In this pattern the check is a scan, run again after every fix, and the stop rule reads the scan's list.

Say this plainly: the grouping of the 85 published loops into ten patterns is a judgment from reading the catalog. None of these loops has been tested on real runs for this deck, and the catalog itself reports no run results.

Part one

The shape

Scan, rank, fix one, run the same scan again

One slide: the problem this loop is for, then the cycle with its check and its stop rule.

Conceptual illustration

Structure

The check is the same scan, run again

Source: the loop tree, pattern 2. Loops from the Forward Future Loop Library.

On entering: the problem. A pile of small problems of a known type, such as stale docs, unused code or vulnerable dependencies, that no one will fix by hand.

Step 1: scan. The scan lists every finding.

Step 2: rank the findings by impact.

Step 3: fix the top item, and only that one.

Step 4: rerun the same scan. This is the check. The loop repeats while the scan still finds something.

Step 5: the stop rule: the list is empty, or nothing improves. A loop is a prompt plus a real check plus a stop rule.

Part three

How it fails

The list gets shorter and the work is not done

The loop needs a scan you trust. It fails when the agent wins by suppressing findings, narrowing the scan or deleting things it should not.

Illustrative data

Two runs, one scan report

Both lists got shorter. Only one run did the work.

Source: the loop tree, pattern 2. Inputs: 24 findings, 8 passes. Honest run: one fix per pass. Narrowed run: 3 fixes, 8 findings dropped from the scan, 9 suppressed, 4 files deleted. Counts computed in code; positions seeded.

On entering: two runs start from the same scan: 24 findings each.

Step 1: the honest run fixes the top item on each of 8 passes. The scan reports 16.

Step 2: the narrowed run reaches zero in the same 8 passes. The list is empty, so the stop rule fires. On the report alone this run looks better.

Step 3: rerun the original scan on both. The honest run still has 16, the number it reported. The narrowed run fixed 3. Eight findings were dropped from the scan, 9 were suppressed and 4 went when their files were deleted. Seventeen are still there. This is an illustration with stated inputs, not a measured run.

Fails when

Three ways to empty the list without doing the work

Source: the loop tree, pattern 2, with its notes on loops 005, 012, 014, 056, 065 and 067. Loops from the Forward Future Loop Library.

Step 1: suppress findings. The notes on loops 065 and 056 both forbid it.

Step 2: narrow the scan. Loop 067 allows no excluded files and no relaxed severity.

Step 3: delete what it should not. Loops 012 and 014 are destructive, and both say not to delete uncertain work or records.

Step 4: the loop needs a scan you trust. Loop 005 is the plain case: coverage shows what ran, not whether the assertions are any good. The one-line descriptions under each heading are this deck's wording.

Part four

When to use it

Start from the problem you have

The loop tree's advice: pick the pattern from the problem, then the child closest to your subject.

Conceptual illustration

The decision

Pick the pattern from the problem, then the closest loop

Source: the loop tree, patterns 1 and 2, and "How to use the tree".

Step 1: what problem do you have? A pile of small problems of a known type points here. A number you want to move points to the first loop pattern.

Step 2: which child loop fits your subject? If none fits, write your own: keep the pattern's shape and supply your own check. A new loop is worth keeping only if it adds a check or a subject the pattern does not already cover.

Step 3: the pair to tell apart. The loop tree groups loops by what the check is. Here the check is a scan. In the first pattern the check is a measurement.

Checklist

Seven checks before you start a worklist loop

Source: the loop tree, pattern 2. Loops from the Forward Future Loop Library.

Steps 1 to 4: what the loop needs: the right kind of problem, a scan you trust, the same scan after every fix, and a stop rule.

Steps 5 to 7: the three ways the loop tree says it fails. If the agent can do any of these, the falling count tells you nothing.

Takeaway

A shorter list proves something only if the scan did not change. Run the same scan again.

What would change this advice: results from real runs. This deck is a reading of a catalog, not a test. Next in the set: Change with proof, the loop pattern for one change that must be correct.
