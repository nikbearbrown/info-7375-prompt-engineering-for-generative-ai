Prompt chaining

One task, split into fixed steps. Each call reads the last call's output.

This deck covers one pattern: prompt chaining. It shows the shape of the pattern, what it costs, and the questions that decide whether to use it. It is the first of five workflow patterns.

Step 4: this deck is prompt chaining, the first workflow pattern.

The claim

Prompt chaining gives each model call one easier job. Every call then waits for the one before it.

Both halves come from the same split. Breaking the task into steps makes each call simpler. It also puts the calls in a line, because each one needs the previous output before it can start.

The shape

A fixed sequence of calls, each fed by the last

Three slides: the chain, a recorded run of four prompts, and the gate that can sit between two calls.

Conceptual illustration

Structure

Each call takes the previous call's output as its input

Source: Anthropic, "Building Effective Agents", "Workflow: Prompt chaining". Code from the cookbook notebook basic_workflows.ipynb, with its print lines removed.

On entering: an input and three calls that have not run.

Step 1: call 1 reads the input with its own prompt and writes output 1.

Step 2: call 2 never sees the original input on its own. It reads output 1.

Step 3: call 3 reads output 2. Its output is the result.

Step 4: in the notebook the whole pattern is a three-line loop. The list of prompts is written before the run. The model does not choose the steps or their order.

A recorded run

Four prompts turn a paragraph into a sorted table

Source: Anthropic cookbook notebook basic_workflows.ipynb, example 1. Outputs are the notebook's recorded run. Prompt names are shortened.

On entering: the input is a short quarterly report in plain sentences. Four prompts wait on the left.

Step 1: the first call only extracts. Nine lines, one value and one metric on each.

Step 2: the second call only converts. Three lines change: 92 points becomes 92 percent, 43 dollars becomes 43.0, and 87 points becomes 87 percent.

Step 3: the third call only sorts. Watch the lines move. Notice the sentence it added at the top. The prompt did not ask for it. We come back to that on the next slide.

Step 4: the fourth call only formats. The result is a table of nine rows.

The gate

A gate is a check in code between two calls

Source: Anthropic, "Building Effective Agents", "Workflow: Prompt chaining". The example gate is written for this slide and run on the notebook's recorded outputs.

On entering: without a gate, whatever one call writes goes straight into the next.

Step 1: the article says you can add programmatic checks on any intermediate step, to confirm the process is still on track. It calls the check a gate.

Step 2: if the check passes, the next call runs. If it fails, the chain stops there.

Step 3: an example. The notebook's chain has no gate, so this one was written for this slide: every non-empty line must read value, colon, metric. The counts are computed from the recorded outputs. Calls 1 and 2 pass, 9 of 9. Call 3 gives 9 of 10.

Step 4: the failing line is the sentence call 3 added. In the recorded run, call 4 still produced the table. The point of the gate is that code decides, before the next call reads the output.

What it costs

More calls, and each one waits for the one before it

The sources name a trade, not a failure mode. This part shows the trade.

Conceptual illustration

The trade

Four calls in a row where one prompt makes one

Source: Anthropic, "Building Effective Agents", "Workflow: Prompt chaining". Call counts come from the notebook's four-prompt example.

On entering: two ways to do the same task.

Step 1: one prompt that asks for all four jobs makes one model call.

Step 2: the chain makes four calls. The bars are drawn the same length to keep the picture simple. Real calls differ.

Step 3: the calls can't overlap. Each one needs the previous output as its input.

Step 4: the article states the trade in one line. The notebook is careful about the gain: it says these workflows trade cost or latency for performance that may improve. Measure it on your own task.

Part three

When to use it

When the task splits cleanly into steps you can fix in advance

The article's first advice applies before any pattern: find the simplest thing that works, and add steps only when they pay for themselves.

Conceptual illustration

The decision

Three questions decide whether prompt chaining fits

Source: Anthropic, "Building Effective Agents", "When (and when not) to use agents" and "Workflow: Prompt chaining".

On entering: three questions, asked in order.

Step 1: the article says to start with the simplest solution. For many applications one well-built call is enough. If it is, stop.

Step 2: prompt chaining suits a task that can be broken cleanly into fixed subtasks. If the steps depend on the input and can't be written down first, this is not the pattern.

Step 3: the chain is slower. Use it when accuracy is worth the wait.

Step 4: the pair to tell apart is the article's own. In a workflow, the calls follow a path written in code in advance. In an agent, the model directs its own process and tool use.

Takeaway

Prompt chaining trades waiting for easier steps. Use it when the steps can be fixed in advance.

What would change this advice: if one call already does the job well, the chain adds only latency and cost. Next in the set: Routing, where the first call chooses which path the input takes.
