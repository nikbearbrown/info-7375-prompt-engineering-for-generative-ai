Tree-of-Thoughts

Branch, score, prune, extend.

This deck covers one pattern: Tree-of-Thoughts. It shows the shape of the pattern, what it costs, and the question that decides whether to use it.

Where this pattern sits

On entering: an empty map. The set of decks covers twenty patterns, grouped by the question each family answers.

Step 1: reasoning patterns. These describe how one agent orders its own thinking and tool calls.

Step 2: workflow patterns. These describe how several model calls are wired together.

Step 3: loop patterns. These are grouped by the check that keeps a long run honest.

Step 4: this deck is Tree-of-Thoughts, the fifth and last reasoning pattern.

The claim

Tree-of-Thoughts scores several paths before it commits. Every branch it looks at is a model call.

Both halves come from the same mechanism. The pattern keeps more than one candidate alive, which is how it avoids a dead end. Each candidate it keeps alive has to be written and scored, which is what it costs.

Illustrative data

Structure

One round keeps the best few candidates, not just one

Source: Chapter 3, "The Five Patterns: A Structural Taxonomy", Tree-of-Thoughts. Pattern proposed by Yao et al., 2023. Scores are illustrative.

On entering: one task and the four moves of a round. The example uses 3 candidates per step and keeps the top 2.

Step 1: branch. The model writes three candidate next thoughts instead of one.

Step 2: score. A value function rates each candidate. The numbers here are made up for the example.

Step 3: prune. The top two are kept. The third is dropped and never expanded.

Step 4: extend. Each kept candidate branches again, the six new candidates are scored, and again only the top two survive. The chapter compares this to beam search in machine translation.

Why it helps

The best path started from the second-best first step

Source: Chapter 3, "The Five Patterns: A Structural Taxonomy", Tree-of-Thoughts. Same example tree, scores are illustrative.

On entering: the same tree with every score showing, so both strategies can be compared.

Step 1: greedy reasoning commits to the single most probable next step. Here that is A.

Step 2: nothing under A scores well. This is the dead end the chapter describes: the first plausible direction has to be backed out of.

Step 3: keeping the top two first steps kept B alive, and B leads to the highest score on the tree. The example is constructed to show the case the chapter names, where the best path is not obvious from the first step.

Illustrative data

The scorer

A value function scores each candidate before anything is pruned

Source: Chapter 3, "The Five Patterns: A Structural Taxonomy", Tree-of-Thoughts. Scores are illustrative.

On entering: three candidate thoughts wait to be scored.

Step 1: the chapter lists three things the value function can be: another model call, a heuristic, or an external verifier.

Step 2: it returns a score for each candidate.

Step 3: only then does the pattern decide which branches to prune and which to extend. If the value function is itself a model call, it adds to the number of calls counted on the next slides.

Part two

How it fails

Token budget exhaustion: every branch expansion is a model call

The failure comes from the same property that made the pattern useful. Looking at more paths means paying for more paths.

Computed

The worst case

Every level multiplies the number of candidates by B

Source: Chapter 3, "The Five Patterns: A Structural Taxonomy", Tree-of-Thoughts. Counts computed in code as B to the power D, with B = 3.

On entering: one task, and nothing pruned. Every candidate will branch into three.

Step 1: depth 1 has 3 candidates.

Step 2: depth 2 has 9. The running total is 12.

Step 3: depth 3 has 27. The running total is 39.

Step 4: depth 4 has 81, which is 3 to the power 4. Counting every level, 120 candidates have been written and scored. The chapter states the worst case as order B to the power D evaluations for depth D and branching factor B.

Computed

With pruning

Pruning makes the growth linear. It is still not cheap.

Source: Chapter 3, "The Five Patterns: A Structural Taxonomy", Tree-of-Thoughts. All counts computed in code from B = 3 and k = 2.

On entering: three ways to reach the same depth. One path writes one thought per step. The pruned tree keeps the top 2 at each level and expands only those. The full tree expands everything.

Step 1: at depth 4 the counts are 4, 21 and 120.

Step 2: go to depth 6. One path rises to 6. The pruned tree rises to 33, because each level adds 2 times 3. The full tree rises to 1,092, because each level multiplies by 3.

Step 3: pruning is what keeps the pattern usable, as the chapter says. It does not make it cheap. The pruned tree still scores 33 candidates where a single path writes 6 thoughts.

Part three

When to use it

Only when the best path can't be picked in advance

The decision question comes straight from the cost. If the path is known, the branching buys nothing.

Conceptual illustration

The decision

One question decides whether the branching is worth paying for

Source: Chapter 3, "The Decision Framework", question 5 and the pattern table.

On entering: the fifth and last question of the chapter's decision framework.

Step 1: is the best solution path non-obvious? If several valid paths exist and the best can't be identified upfront, the branching search justifies its token cost. If the path is known, the cost is wasted and any sequential pattern will do.

Step 2: the chapter's table row for this pattern: best for a non-obvious optimal path, breaks on token budget exhaustion.

Step 3: the pair to tell apart. Greedy chain of thought commits to the single most probable next step. Tree-of-Thoughts keeps the top-k candidates and scores each one before choosing.

Six checks before you choose Tree-of-Thoughts

Takeaway

Tree-of-Thoughts buys a better path with more model calls. Use it when the path is not obvious.

What would change this advice: a cheaper value function or tighter pruning lowers the count. It does not change the shape of the cost. This is the last of the five reasoning patterns. The workflow family comes next, starting with prompt chaining.
