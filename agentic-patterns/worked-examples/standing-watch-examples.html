Failure must not create more authority

  • Source unavailableKeep the checkpoint; record the error; enter cooldown.
  • Unclear customer impactLeave the claim unresolved and request review; do not guess.
  • Write outcome uncertainRead the draft and key before retrying.
  • Stop signalExit without a new draft; preserve state and a truthful record.
Illustrative teaching fixture. No agent workflow was run.8 / 10

These are branch conditions, not additional claimed incidents. Failure is not a reason to publish a best guess, bypass a lock, repeatedly retry or expand permissions. Rehearse the stop and crash-recovery behavior in a sandbox before actual unattended use. A denied source or unavailable record is not an empty set. Explicitly report what was not inspected.

A bounded watch prompt

On each authorized nightly wake, acquire the run lock and read fresh repository and release state after the durable checkpoint. Inspect at most 10 commits for user-visible changes; verify claims against diffs and release evidence. Write at most one draft entry, using a durable commit key to prevent duplicates. Never publish or change source. Save draft and key atomically; checkpoint only fully handled commits, leaving later work pending. Record every wake, including NO_CHANGE. Cap at 60 seconds and one read retry; failures trigger a 30-minute cooldown. Preserve state on errors, uncertainty or stop signals. End the trial after seven nights.
Illustrative teaching fixture. No agent workflow was run.9 / 10

A reusable specification for an authorized future watch. It is not an automation request made or installed by this deck. The full state contract and lock implementation are prerequisites. If a source or write outcome cannot be verified, the run cannot declare success. Grant exactly the minimum capabilities required for the draft and record. When a one-entry or inspection cap leaves later commits unhandled, retain them beyond the checkpoint for the next authorized wake.
