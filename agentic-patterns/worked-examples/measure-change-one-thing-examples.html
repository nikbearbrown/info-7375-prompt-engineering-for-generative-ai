Do not optimize forever

  • SuccessTarget met and all fixed guardrails pass.
  • Diminishing returnsStop after two consecutive candidates fail the ≥5% improvement gate.
  • BudgetAt most four candidates or 30 minutes.
  • Invalid comparisonHarness drift or tool error: stop, report last valid build.

The success path uses three candidate evaluations, excluding the baseline and restoration check. Any rejected candidate consumes one candidate slot; changing the benchmark does not reset the budget. A candidate that reduces bytes but violates a guardrail is reverted. If the target is unreachable within the limits, return the accepted 142 KB or other best valid build with INCOMPLETE status, not an invented success. The shown path stops at b3.

A bounded measurement prompt

Reduce the demo editor’s cold-load JavaScript from the recorded 186 KB baseline to ≤120 KB. Use the pinned cold-load harness and immutable functional/visual gates. Make one source/import change per candidate. Compare with the current accepted build; keep only reductions of at least 5% with 12/12 scenarios and 6/6 screenshots passing. Otherwise revert and recheck. Stop on success, two consecutive rejected candidates, four candidates or 30 minutes. Stop on measurement drift or tool failure. Return byte logs, candidate decisions, the final diff and unmeasured risks. Do not release.
Illustrative teaching fixture. No agent workflow was run.9 / 10

Use this recipe only after supplying real pins and a baseline from the actual environment. The app, counts and baseline here are fixture values, not facts about the user’s software. A guardrail failure is not permission to edit the guardrail. The independent harness should reject unauthorized changes to its own inputs.
