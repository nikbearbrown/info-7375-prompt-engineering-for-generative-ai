Stop with success or an honest remainder

  • SuccessZero findings, unchanged contract, all behavior checks pass.
  • No progressRevert a repair that reduces nothing; stop and report it.
  • BudgetAt most four patches or 20 minutes, whichever comes first.
  • FailureTool error or scope drift means BLOCKED, never a zero count.
Illustrative teaching fixture. No agent workflow was run.8 / 10

The shown path uses three patches and reaches the success gate. If a patch causes a new regression, revert it and return the remaining list instead of silently trading defects. A safety or authorization blocker ends the run immediately. A budget exit reports INCOMPLETE with completed repairs, remaining IDs and the last valid scan. Real wall-clock enforcement belongs to the harness, not to a hope in the prompt.

A bounded worklist prompt

On the demo ticket branch, reduce findings from a11y-contract@1 to zero. Preserve its two surfaces, two widths, rules and keyboard cases. Edit only the form, dialog and their styles. Rank findings by task impact; repair one, rerun the entire frozen scan and behavior tests, then keep or revert. Never suppress, exclude or delete UI to improve the count. Stop at zero, the first non-improving repair, four patches or 20 minutes. On tool failure, stop BLOCKED. Return the diff, before/after issue IDs, check outputs and unchecked scope. Do not deploy.
Illustrative teaching fixture. No agent workflow was run.9 / 10

This is a reusable recipe for an owner-authorized local run, not an instruction executed while making this deck. Supply the actual repository, harness version, baseline and ownership before using it. A prompt alone does not protect the checker; file permissions and diff gates enforce the protected scope.
