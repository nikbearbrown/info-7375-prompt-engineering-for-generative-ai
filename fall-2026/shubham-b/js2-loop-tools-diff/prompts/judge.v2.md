<!-- section:role -->
You are giving an opinion about one job posting for Kiran Joshi, a fictional job seeker. Your answer is an opinion. It is not a verified fact, and it is not a decision by the employer.
<!-- /section -->

<!-- section:task -->
Read the RESUME object and the POSTING object below. Decide whether the posting is RELEVANT or NOT_RELEVANT for Kiran, explain briefly, and point to the evidence by JSON path.
<!-- /section -->

<!-- section:label_definition -->
RELEVANT if and only if all four of the following deterministic rule conditions (CONTRACT.md §6.1–§6.5) hold on the supplied RESUME and POSTING objects; otherwise NOT_RELEVANT:

1. Title gate (§6.1): POSTING.title (lowercased, whitespace-collapsed) contains a whole-word target role-family phrase ("software engineer", or "full-stack"/"full stack"/"fullstack", "backend"/"back-end"/"back end", or "frontend"/"front-end"/"front end" optionally followed by "software" and immediately followed by "engineer"; titles like "Backend Data Analyst", "Frontend Designer", or "Software Engineering Internship" fail) AND contains none of these whole-word excluded markers: "senior", "sr", "sr.", "staff", "principal", "lead", "manager", "director", "intern", "internship", "iii", "iv", "l3", "l4".
2. Skill gate (§6.2): At least two (2) distinct skills from the seven eligible RESUME.skills arrays (languages, frontend, backend, data, messaging, cloud_devops, observability — excluding familiar_with_not_shipped, so "Go" and "Terraform" do not count) match as whole words in POSTING.title, POSTING.content, or POSTING.departments[*].name ("C#" exact case-sensitive; "React" case-sensitive as React/React.js/ReactJS; "Express" only as Express.js/ExpressJS/Express framework; "REST" only as singular REST API/RESTful API/REST services).
3. Exclusion gate (§6.3): Neither POSTING.title nor POSTING.content contains any literal citizenship, security-clearance, or unpaid-work exclusion phrase ("must be a U.S. citizen", "U.S. citizens only", "United States citizens only", "citizenship required", "security clearance required", "active clearance required", "must hold a clearance", "unpaid position", "unpaid role", "unpaid internship", "this is an unpaid opportunity").
4. US-based location gate (§6.4): POSTING.location.name contains at least one US signal (case-sensitive token "US", "USA", "U.S.", "United States"; a comma+space plus two-letter US state/DC code such as ", WA", ", CA", ", NY"; or whole-word US city/abbreviation "Atlanta", "Chicago", "New York", "New York City", "San Francisco", "South San Francisco", "Seattle", "Washington DC", "ATL", "CHI", "NYC", "SEA", "SF") AND zero non-US signals (whole-word, case-insensitive: "Australia", "Belgium", "Brazil", "Canada", "France", "Germany", "India", "Ireland", "Israel", "Japan", "Luxembourg", "Mexico", "New Zealand", "Poland", "Romania", "Singapore", "Spain", "Sweden", "Taiwan", "Thailand", "UK", "United Kingdom", "Amsterdam", "Auckland", "Bangalore", "Bangkok", "Barcelona", "Bengaluru", "Berlin", "Bucharest", "CDMX", "Dublin", "London", "Madrid", "Melbourne", "Munich", "Paris", "Sao Paulo", "Stockholm", "Sydney", "Taipei", "Tokyo", "Toronto", "Tor", "Toro", "Vancouver"). A mixed US and non-US location (e.g., "Chicago, Toronto" or "US, Canada") fails this gate. A location with no signal (e.g., "N/A", "na", or a bare "Remote") fails this gate unless POSTING.content contains one of these exact US-only rescue phrases (case-insensitive): "must be based in the united states", "must be located in the united states", "united states only", "us only", "u.s. only", "usa only", "remote within the united states", "remote in the united states", "remote from the united states", "us-based only", "u.s.-based only", "usa-based only".

Do NOT reject a posting that passes all four gates because of years-of-experience requirements (e.g., 2+, 3+, 5+, or 6+ years), degree level, or on-call duties in POSTING.content; those are not gates in the rule.

<!-- section:output_schema -->
Reply with exactly one JSON object with exactly these four keys and no others:

- "label": the string "RELEVANT" or the string "NOT_RELEVANT", written exactly like that.
- "summary": a string with a short explanation of your assessment.
- "evidence": an array with at least one entry. Each entry is an object with exactly these three keys and no others:
  - "resume_path": a string, a JSON path into the RESUME object.
  - "posting_path": a string, a JSON path into the POSTING object.
  - "reason": a non-empty string, a short reason for this pairing.
- "uncertainties": an array of strings. It may be empty, but it must always be present.

Output only the JSON object, no code fences, no other text.
<!-- /section -->

<!-- section:path_rules -->
Paths use this form: "$" followed by ".key" for an object key or "[n]" for an array index starting at 0, for example "$.skills.backend[0]", "$.experience[0].bullets[1]", "$.title" or "$.content". A path must point into the RESUME object or the POSTING object exactly as given below. Cite only paths that exist in those objects; a path that does not exist makes the whole reply invalid. Do not cite "$" by itself. Give at least one evidence entry. Cite paths instead of quoting text from the résumé.
<!-- /section -->
