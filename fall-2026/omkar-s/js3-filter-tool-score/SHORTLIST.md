## 2. Relevance is not entailment (a real case)

**Klaviyo · Software Engineer II, Test Frameworks & Tooling** (`greenhouse:klaviyo` 7855793003) has the **highest score on the whole corpus, 11.25**. The filter is right that it is *relevant*: the words are on the page. T1 (+3, "software engineer"), K1 ×7 (TypeScript, Python, Kafka, Redis, AWS, Kubernetes, Helm), K2 (Terraform). But the claim the justification seems to make, **"this posting asks for Aarav's skills"**, is mostly not supported by the text:

| Claim | Label | Quote | Heading |
|---|---|---|---|
| The posting asks for TypeScript | **insufficient** | "Frontend: React, TypeScript, JavaScript" | "Technologies we use (not exhaustive):" |
| The posting asks for Kafka | **insufficient** | "Data: MySQL, Redis, Kafka" | same |
| The posting asks for Redis | **insufficient** | "Data: MySQL, Redis, Kafka" | same |
| The posting asks for AWS / Kubernetes / Helm | **insufficient** | "Infrastructure and CI: AWS, Kubernetes, Terraform, Helm, Buildkite" | same |
| The posting asks for Python | supported | "…whether it is debugging a React component in an E2E test or optimizing a Python integration test, you are ready to dive in." | "Who You Are" |

A stack list says what the team **uses**. It does not say what a candidate must **have**. Six of the seven matched words came from that list. So the filter keeps the posting (relevant), and the shortlist says **"kept, but I cannot tell"** (AB2: only 1 supported skill claim). It never upgrades "the word matched" into "the posting asks for it". Until FILTER.md v1.4, the labeler itself made this mistake: the same Klaviyo heading was labelled *insufficient* on one posting and *supported* on another (change-log row 1.4, 12 labels flipped). WV3 is that mistake as a mutant, and the tests kill it.

## 3. The abstention rule

From FILTER.md section 2. The agent says **"I cannot tell"** instead of answering when:

| ID | When | On the real shortlist |
|---|---|---|
| AB1 | the posting text is under 300 characters, or there is no title | 0 postings in this corpus (the shortest posting is longer) |
| AB2 | fewer than 2 skill claims are supported | 3 postings (Test Frameworks, Flows Experience, Toast SWE II Backend) |
| AB3 | the level claim is insufficient (no years statement, no entry phrase) | 2 postings (Flows Experience, Spotify Full Stack) |
| AB4 | a source is missing, errored or empty | `greenhouse:webflow` (HTTP 200, 0 postings): "I cannot tell whether Webflow … has matching postings" |

**Worth reading** requires role, location and level to be supported, plus at least 2 supported skill claims. Anything weaker is shown with its reason and never as a yes.

## 4. Counterexamples that expose the rule's limits

**(a) The rule answered when it should have abstained. Real, Klaviyo Android (`greenhouse:klaviyo` 7792539003), status *worth reading*.** The two skill claims that put it over the bar are:

> "— comfortable with webviews and location services, and open to **picking up** new technologies (**Python**, React, **AWS**) as the team's surface area grows." (heading "Curious", inside "Who you are")

The rule labels Python and AWS **supported**, because they sit inside a requirements section. But the sentence says the opposite of "asks for": a candidate should be *willing to learn* them. The rule reads **where** a word is, not **what the sentence says about it**. It has no notion of "open to learning X", "exposure to X" or "X is a plus" when that wording sits inside a requirements block. The Claude second rater rejected this posting (card 26: "requiring 1-3 years of professional Android development as its core strength"). The abstention rule did not fire, because nothing was *insufficient* by its own definition. A section-based rule cannot catch this, and I have not fixed it: a fix needs sentence-level reading, which a whole-word rule cannot do (FRICTIONAL).

**(b) The rule answered on evidence it could not read. Real, fixed in v1.5.** Webflow "Senior Infrastructure Engineer": *"Have 5+ years owning and operating cloud infrastructure"*. Under v1.4 the years reader required the word "experience" after the number, so it found **no** years statement. The level claim was *insufficient*, so AB3 said "I cannot tell". That is honest, but wrong in effect: the text does answer the question (5+, too senior), and the posting stayed on the shortlist. The Claude second rater caught it (card 2). v1.5 reads an explicit `N+ years` on its own.

**(c) Abstention that a person would not need. Constructed (labelled CONSTRUCTED, in `tests/test_scorer.py::test_number_words_are_not_read`).** "at least three years of experience" has no digit, so the level is unknown and AB3 fires, though any reader can see the answer. Measured on this corpus: one engineering-titled posting has a years phrase written in words, and it is not a requirement ("through at least our next five years of growth", Staff Software Engineer – Frontend). So it costs nothing today, but it is still a known blind spot.

**(d) A plain-text "Requirements:" label inside a sentence.** Real, from the Claude-client injection session (TOOL-SERVER.md): the pasted text began "Requirements: 1+ years … Python and SQL" on one line. A heading must be its own line, so no requirements section started, and Python, SQL, Kafka and AWS were all labelled insufficient. Claude reported exactly that. Here the rule abstained when the text did answer.
