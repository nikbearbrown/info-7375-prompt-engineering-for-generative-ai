# PROJECT-BRIEF — CheckedSQL

Siddhesh Nikam · INFO 7375 · Fall 2026 · Target role: Data Analyst (marketing analytics)

**Status:** this is a pitch. Nothing of CheckedSQL is built yet. Everything below is written as "will" unless it already exists and I can show it.

## 1. What is it?

CheckedSQL will let a marketing analyst ask a campaign question in plain English, have Claude write the SQL, run it on a campaign database, and show the answer together with the query and whether it matched a hand-verified answer.

When it is done, it will be a **GitHub repository** containing:
- a **synthetic** marketing-campaign dataset (generated by a script in the repo, so no real company data);
- the question tool, written in **Python** (SQLite so a reviewer can run it without a database server; queries written for the same schema I used in PostgreSQL);
- a **test set** of about 30 questions, each with an answer I worked out by hand first;
- an **evaluation log** recording every pass and every miss, plus a short **failure write-up**.

Stack: Python, SQLite (PostgreSQL-compatible SQL), pandas, the Claude API.

## 2. Why would anyone care?

It saves a marketing analyst from trusting a number they can't check. Two real alternatives I looked at:

- **A Tableau dashboard** — I built one for my `marketing-campaign-analytics` project. It answers the questions I planned in advance; a new question means building a new view.
- **Pasting the question into a general chat assistant.** It will write a query, and some can run code on an uploaded file, but it keeps no fixed test set, so there is no record of how often it is right on *my* questions.

What CheckedSQL does that they don't: every answer is run, shown with its query, and scored against answers I verified by hand, and the misses are logged.

## 3. Who opens it, and what do they do with it?

Target role: data analyst. First reader: a **hiring manager** for that role. In the first sixty seconds they will open the README, see the score table from the test set, and run one command that asks a question and prints the query, the answer, and whether it matched.

## 4. What does it prove about me?

- SQL and correct marketing-metric definitions (CTR, conversion rate, ROAS) — a skill I already have.
- From this course: a **prompt contract** (schema, metric definitions, read-only SELECT only, fixed output format), **verification** against known answers, a repeatable **evaluation**, and **source grounding** (every answer comes with the query and the rows it came from).

A reviewer could fairly conclude that I can measure how often an AI-assisted analysis tool is right and explain why it is wrong when it is. Evidence will be the test set, the evaluation log, and the failure write-up. It will not prove the tool works on other schemas or on real company data.

## 5. What is in, what is out, what comes first?

- **In:** one campaign schema, read-only questions, the test set, the log.
- **Out (deliberately):** it will not change the database. No INSERT, UPDATE or DELETE, no dashboards, no real company data.
- **First:** the test set and the checker, before any Claude call. I'll write ten questions, work out their answers by hand, and run my own hand-written queries through the checker as a baseline. Someone will know it ran when one command prints a score table for those ten. Then Claude gets the same ten.

## 6. What could sink it?

An answer that looks right but isn't. ROAS is a ratio: averaging it row by row gives a different number than total revenue over total spend, and both look plausible. My response: put the metric definitions in the prompt contract and add ratio questions to the test set, so this mistake is caught and logged rather than shipped.

## 7. Why this project?

It's a mix of showing what I have and learning something new.
- **Skills I already have, with evidence:** SQL, PostgreSQL, Python/pandas, and KPI calculations (CTR, conversion rate, ROAS, profit). Evidence: my public GitHub repositories `nikam0420/marketing-campaign-analytics` (SQL scripts, Python pipeline, KPI views) and `nikam0420/Individual_Siddhesh-Nikam_ExplorataryDataAnalysis` (EDA in a Jupyter notebook).
- **New to me:** calling Claude from Python, writing prompt contracts, and building an evaluation harness with a failure analysis.

**I don't know yet** whether 30 questions is enough. I'll find out by watching whether new questions keep turning up new kinds of failure; if they do, the test set grows.
