# WRONG_VERSIONS.md

| # | Wrong Version | Why It Looks Right | Test That Catches It |
|---|---|---|---|
| 1 | Marking a run `finished` when a response returns 200 OK but has no jobs. | 200 OK looks like success, JSON parses cleanly, and no network error was thrown. | Seed Greenhouse with `{"jobs": []}` and Lever with `[]`; check that both exit as `incomplete` instead of `finished`. |
| 2 | Charging a skipped duplicate against the 15-request budget. | It counts every loop iteration as an action, so the tally looks complete. | Pass duplicate board URLs; check that the duplicate is logged as skipped, total requests used equals unique boards fetched, and the budget counter does not increment for the skipped board. |
| 3 | Treating normalized URL variants (e.g., lowercase vs uppercase, or trailing slash vs no slash) as separate boards and fetching both. | Simple string equality says the URLs are different, and both return 200 OK. | Give two URLs for the same board with differing cases or trailing slashes; check that the network client is called only once. |
| 4 | Retrying a 404 response once before stopping. | It reuses a generic "retry on failure" helper without checking status code category. | Mock a 404 response; check that the request count for that board is exactly 1 and status immediately marks `failed`. |
| 5 | Retrying a failed board twice because the total run is still under 15 requests. | There are spare requests left in the overall budget, so extra retries look harmless. | Mock continuous 500 errors; check that the loop attempts the board at most twice (1 call + 1 retry) and then stops retrying it. |
| 6 | Substring-matching allowed hostnames (e.g. `'boards-api.greenhouse.io' in host`). | It matches legitimate API URLs and blocks obvious bad domains. | Pass `https://boards-api.greenhouse.io.evil.com/v1/boards/x/jobs`; check that the policy rejects the URL before any request goes out. |
| 7 | Using simple prefix checks like `path.startswith("out/")` to validate file writes without resolving canonical paths. | Paths like `out/jobs.json` pass, making the output folder look safely bounded. | Try writing to `out/../boards.json` or `out-evil/data.json`; check that the path validator resolves real paths and blocks the write. |
| 8 | Allowing symlinks inside `out/` that point to files or folders outside `out/`. | The target path starts with `out/` and lives inside the allowed directory. | Make a symlink inside `out/` pointing to the project root; try writing through it; check that the policy checks `realpath` and blocks the write. |
| 9 | Writing to protected files (`boards.json`, budget config, `GATE.md`) without `--approve`. | Updating files during the run keeps things working smoothly without crashing. | Attempt a write to `boards.json` without `--approve`; assert the write is blocked, logged, and exits the run with `error`. Then run with `--approve` and assert the write succeeds. |
| 10 | Retrying a 500 error immediately in a tight loop without waiting the required 2 seconds. | It respects the one-retry rule and tests run faster without sleeping. | Mock a 500 error with an injected mock sleep function; assert the mock sleep was called with 2 before the second attempt. |
| 11 | Recording a failed board in the final report as having `jobs: 0`. | Every board in the report gets a clean number, which looks tidy and complete. | Send a 404 or failed board; assert its entry has `status: failed` and does not include a fake `jobs: 0` count. |
| 12 | Checking the 60-second time budget only after the loop finishes all boards. | The run still ends up reporting `budget-exhausted` at the very end. | Set a mock clock so the first board takes 65 seconds; assert the loop halts immediately on `budget-exhausted` before dispatching a request to the second board. |
