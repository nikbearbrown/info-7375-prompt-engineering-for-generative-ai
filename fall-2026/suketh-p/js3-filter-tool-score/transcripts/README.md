The scripted messages are in [scripts/](scripts/), each step with a note saying what it probes. [scripts/demo-postings.json](scripts/demo-postings.json) names the two saved postings used in the demonstrations. Both were picked by code from outside the hand-label sample and the shortlist, so neither transcript shows the filter's decision on a posting the student labels.

**What the audit hook can and cannot show.** It is installed before the server's own code runs, through `sys.addaudithook`, and it reports `open` (with read or write access), socket, process and file-deletion events to standard error. That is evidence about these runs, on these inputs, of this version. Code can avoid audit events (native extensions, `ctypes`), and Python's start-up imports happen before the hook. So "no write was seen" is a finding about a run, not a guarantee about the program.
