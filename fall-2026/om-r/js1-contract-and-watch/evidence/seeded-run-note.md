## Why it is seeded

The assignment (Step 2) requires two runs with a real change between them:
"a second calendar day, or a second run against a saved earlier response,
clearly labeled as seeded." The deadline (2026-10-31) is too close to rely on
GitLab's board changing on its own, so this run uses option two. A real
live second run is still being attempted on 2026-10-31. If one turns up a
genuinely new posting, it is logged separately as a bonus run.
