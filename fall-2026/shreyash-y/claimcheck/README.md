# ClaimCheck: first runnable piece

## Executive summary

ClaimCheck answers questions about an insurance claim file only with a word-for-word quote from
the documents, and a plain-code checker blocks any answer whose quote it cannot verify. This folder
is the first piece promised in my pitch film (beat B08): **one synthetic policy, 10 frozen
questions, the citation checker, and a dated eval report**. It runs offline with one command; the
live Claude run is a separate, explicit step.

## Run it

```bash
python3 -m claimcheck.eval                 # offline baseline, no key, writes reports/eval_report-<date>-baseline.md
python3 -m unittest discover -s tests -v   # 17 offline tests
```

Live Claude run (costs a few cents; needs `ANTHROPIC_API_KEY` in your shell and `pip install -r requirements.txt`):

```bash
python3 -m claimcheck.eval --answerer claude
python3 -m claimcheck.eval --answerer recorded --responses runs/<run>/responses.jsonl   # replay it offline
```

## What's here

| Path | What it is |
|---|---|
| `data/policy_ho3_synthetic.md` | one synthetic homeowner policy, written for this project. Endorsement E-2 overrides exclusion 5(d) |
| `data/questions.jsonl` | 10 questions with gold status, gold text and source. 4 are traps (an override, 2 not-in-documents, an exception inside an exclusion) |
| `data/FROZEN.md` | the question set's sha256, frozen 2026-10-25 before any Claude run. The eval refuses to run if it changes |
| `claimcheck/contract.py` | the answer contract: `answer`, `quote`, `doc_id`, `status`; parse or reject |
| `claimcheck/checker.py` | the citation checker (standard library only). Rules are listed at the top of the file |
| `claimcheck/grading.py` | grades each question against gold: WRONG, MISSED, CAUGHT, CORRECT |
| `claimcheck/answerers.py` | `baseline` (no model), `claude` (live, explicit), `recorded` (replay of a saved Claude run) |
| `claimcheck/eval.py` | runs the set and writes the dated report, failures first |
| `reports/` | dated eval reports, each generated by `eval.py` and not edited by hand |
| `runs/` | raw Claude replies from live runs, kept so a run can be replayed and checked |
| `FRICTIONAL.md` | dated log for this piece |

## What the first run showed

The first report (`reports/eval_report-2026-10-25-baseline.md`) uses the no-model baseline, not
Claude. The baseline copies a whole document line as its answer, so every quote verifies, and
4 of 10 answers were still wrong (it picked the base exclusion instead of the endorsement, and it
answered both not-in-documents questions). **The checker makes an answer traceable; it does not
make it right.** Grading against frozen gold text is what catches a real quote from the wrong
clause. A test (`test_real_quote_from_the_wrong_clause_passes_the_checker_but_grades_wrong`) pins
that limit down so it can't be forgotten.
