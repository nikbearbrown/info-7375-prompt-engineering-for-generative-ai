# Primary technical references

Checked 2026-09-06. Product capabilities can change; select a model available to the student's account and record it with each live experiment.

- [Northeastern Claude portal](https://claude.northeastern.edu/): institutional onboarding, SSO, support, data-use guidance, and API-access inquiries. The instructor supplies this course's Claude Code-access assumption.
- [Claude Code quickstart](https://code.claude.com/docs/en/quickstart): installation and account sign-in.
- [Claude Messages API](https://platform.claude.com/docs/en/api/messages/create): request envelope, system field, content blocks, and output budget.
- [Claude tool result handling](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls): matching tool IDs, error results, and preserving conversation content.
- [Claude models overview](https://platform.claude.com/docs/en/models/overview): verify current model IDs and supported settings before live coursework.
- [MCP lifecycle, 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle): versioned initialization and capability negotiation for the Week 8 teaching subset.
- [Python standard library documentation](https://docs.python.org/3/library/): pathlib, unittest, urllib, json, math, threading, and difflib reference for the implementations.

These links support the technical integrations, not the unresolved administrative policies in the supplied syllabus. The small training example is an original binary logistic regression implementation, not a reproduction of Claude training.
