# GitHub version posting — 10 points

**Course AI policy:** [AI Policy for Professor Bear's Courses | Using AI Responsibly in Class](https://youtu.be/8Ut0Cdl6vMw?si=9w3aEpt1ZyAR4Kiz).

For each graded Assignment, post a properly organized version to GitHub and upload the matching version to Canvas. This category assesses delivery and traceability, not implementation quality, effort, or video production.

| Criterion | Points | Full-credit evidence |
|---|---:|---|
| Correct location and reviewer access | 2 | Use `fall-2025/first-name-last-initial/assignment-XX/`. The instructor/TAs can open the repository and assignment folder. |
| Complete, organized version | 2 | Include the required implementation, tests, supporting evidence, and FRICTIONAL.md; omit caches and unrelated files. |
| Usable README | 2 | Identify the assignment and student, list contents, provide setup/run/test commands, and credit starting sources and assistance. |
| Identifiable submitted revision | 2 | Commit and push the intended version; provide a GitHub folder link and final commit hash in Canvas. A local-only commit is not a GitHub posting. |
| Canvas consistency and safe sharing | 2 | Canvas contains the matching submitted version. Exclude credentials, restricted data, and private conversations. |
| **Total** | **10** | |

Each row: 2 = complete, 1 = partial, 0 = absent. This category does not regrade code correctness or the substance of Frictional. A video is not required.

Example: `fall-2025/jane-d/assignment-01/` containing `README.md`, `FRICTIONAL.md`, implementation, tests, and evidence. Use lowercase kebab-case names. If names collide, obtain an instructor-approved distinguishing suffix; do not overwrite another student's work.

Keep practice in ignored `learning-artifacts/`, then copy the intended sanitized submission into the tracked semester folder. Use the instructor-designated repository or submission workflow; do not infer permission to push to a shared repository or expose restricted material. Private repositories must grant reviewer access.

Use meaningful commit subjects describing the change. Link a relevant Frictional entry when useful. Commit volume is not a grading criterion. Put the final hash in Canvas rather than trying to embed a commit's own hash inside itself. If revising afterward, identify and resubmit the new matching version under the published resubmission rules.
