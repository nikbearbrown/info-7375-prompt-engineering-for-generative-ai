## B01
Begin small. Ask for one case with five specific questions, and ask the coach to wait for your answers. The instructions default to one case. You can also request one multiple-answer question, a topic drill, or a full practice paper.

## B02
The full paper has one hundred points. Five case questions contribute fifty. Ten multiple-answer questions contribute fifty more. Each case must print five specific questions. Short numbered answers are enough; this is not an open essay.

## B03
Check the case before answering. Its five questions should ask you to identify a supported defect, name the concept, propose a check, rewrite the instruction, and explain the consequence plainly. The points are three, two, two, two, and one.

## B04
For multiple-answer practice, judge each of the five statements independently. Any number can be true. A true statement checked correctly earns one point, and a false statement left unchecked correctly also earns one. Do not hunt for an answer pattern.

## B05
Submit your attempt before requesting feedback. The coach should not reveal the diagnosis or worked solution beside the question. After your attempt, it can give targeted practice feedback and rubric scores. Private instructor keys never belong in the student-facing project.

## B06
The embedded starter notes make this prompt self-contained. They cover prompt contracts, tool permissions, agent loops, and other taught mechanisms. No extra upload or live API call is needed. Optional course files can improve source-specific fidelity, but the coach must not pretend to read files you did not supply.

## B07
One caveat matters. The compact list prioritizes prompting, agents, loops, generation, tools and integration. The larger term inventory is still being narrowed by the instructor. This draft is not a confirmed final exam blueprint. Generated questions still need review.
